### 1.3 產業現況與對策

美髮產業的顧客決策路徑，九成以上發生在手機上：
IG／Google 地圖 → 看作品 → 看設計師 → 看價格 → 預約。

目前多數台灣沙龍網站有三個共同問題：

| 問題 | 現象 | 本站對策 |
|---|---|---|
| 作品集雜亂 | 每位設計師自己用手機拍，白平衡、角度全不同，滑下來像五間店 | 統一拍攝規範 + 分類篩選 |
| 預約斷點 | 網站只放電話，顧客要跳出去 LINE 再等回覆 | 全站常駐預約 CTA，一鍵到底 |
| 只有形象沒有信任 | 大圖美美的，但看不到「誰會服務我」 | 設計師個人頁為核心資產 |

### 1.4 品牌設計原則與內容限制

品牌叫「留白」，所以留白是**規格**，不是感覺。
以下為原則與內容上限；實際數值（間距、字級）定義於另一份設計系統文件。

**四條原則**

1. **一屏一件事** — 每個區塊只傳達一個訊息，不並列兩個主張
2. **減法優先** — 新增元素前，先問能不能拿掉別的
3. **留白是主角** — 區塊間距明顯大於業界慣例，寧可頁面長，不要頁面擠
4. **一個主按鈕** — 每個區塊最多一個強調色按鈕，其餘為文字連結

**內容字數上限（撰稿依據）**

| 內容 | 上限 | 原因 |
|---|---|---|
| Hero 主標 | 12 字 | 一行顯示，手機不折行 |
| Hero 副標 | 25 字 | — |
| 品牌故事 | 300 字 | 原 500 字，留白後頁面過長 |
| 服務卡片描述 | 20 字 | 卡片高度一致 |
| 設計師自我介紹 | 200 字 | — |
| 理念卡片標題 | 8 字 | — |
| FAQ 單題答案 | 100 字 | 超過改開獨立頁 |

**因留白調整的結構**

- 首頁區塊由 9 個 → **7 個**（「顧客評價」併入設計師頁、「髮型誌摘要」縮為 Footer 上方精簡列）
- 作品集網格：手機 1 欄、平板 2 欄、桌機 **3 欄**（不做 4 欄）
- 價目表每個分頁籤最多顯示 8 個品項，超過分組

## 2. 網站目的

### 2.1 商業目標（依優先序）

1. **產生預約** — 首要且唯一的轉換行為
2. **建立品牌信任** — 讓陌生客敢走進店裡
3. **降低溝通成本** — 價格、地址、停車、服務內容前置說明，減少重複問答
4. **輔助招募** — 吸引設計師與助理應徵

### 2.2 成功指標（KPI）

| 指標 | 目標值 | 量測方式 |
|---|---|---|
| 預約 CTA 點擊率 | ≥ 8%（工作階段） | GA4 事件 |
| 完成預約數 / 月 | 依現況 +30% | 預約系統後台 |
| 平均工作階段時間 | ≥ 90 秒 | GA4 |
| 品牌關鍵字自然流量 | 3 個月內成長 50% | Search Console |
| 手機跳出率 | ≤ 55% | GA4 |

### 2.3 非目標（本期不做）

- 線上商城／商品販售
- 會員積點系統
- 多語系（僅繁體中文）
- 部落格自動化內容產製

## 3. 目標受眾

### Persona A — 換設計師的探索型顧客（主力，約 55%）

- 25–40 歲女性，剛搬家或對原設計師不滿
- **在意**：作品風格是否符合自己、會不會被推銷、價格透明度
- **痛點**：不敢預約沒看過作品的設計師
- **網站任務**：先看作品 → 鎖定設計師 → 預約指名

### Persona B — 高單價需求客（約 25%）

- 30–45 歲，做接髮、頭皮養護、髮質重建等高單價項目
- **在意**：專業度、藥劑品牌、有沒有做過類似案例
- **痛點**：怕花大錢做壞
- **網站任務**：看服務說明 → 看 Before/After → 諮詢

### Persona C — 附近臨時客（約 15%）

- 從 Google 地圖點進來，只想剪個頭髮
- **在意**：地址、營業時間、今天有沒有位、多少錢
- **網站任務**：3 秒內找到價格與預約

### Persona D — 求職設計師（約 5%）

- **在意**：抽成制度、教育訓練、店內氛圍
- **網站任務**：加入我們頁

## 12. 決策記錄（Decision Log）

記錄「為什麼這樣決定、放棄了什麼」。設計提案時比 Wireframe 更有說服力。

### D-01 不使用 LINE 預約

- **決定**：全站不放 LINE，預約走官網流程
- **放棄**：台灣顧客最熟悉的預約習慣，短期可能流失部分客人
- **理由**：LINE 預約會讓設計師在服務中不斷回訊息，違反「一次只服務一位客人」的核心定位。且訊息預約無法留下結構化資料，無法分析。
- **風險與對策**：保留電話預約作為退路；`/booking` 頁首直接說明原因，把限制轉為主張

### D-02 自建預約 UI，不嵌入第三方 widget

- **決定**：自己設計五步驟流程，後端串 SimplyBook.me API
- **放棄**：開發時間（嵌入 widget 半天，自建約 2 週）
- **理由**：預約是全站唯一轉換行為，也是最能展現品牌與 UX 的地方。嵌入 widget 等於把最重要的頁面外包給別人的視覺。
- **風險與對策**：先做可用版本（步驟 1–5），通知信與付訂金功能延後

### D-03 價格全公開

- **決定**：公開完整價目，含長髮加價與職級價差
- **放棄**：詢價制帶來的彈性報價空間
- **理由**：Persona A 最大的恐懼是「怕被推銷、怕被加價」。透明定價直接消除它，也降低來電詢問成本。
- **風險與對策**：標示「起」價與加價條件，避免糾紛

### D-04 首頁區塊 9 → 7

- **決定**：移除顧客評價與髮型誌摘要區塊
- **放棄**：首頁的資訊完整度
- **理由**：留白原則下區塊間距加大，9 個區塊會讓手機頁面過長。評價綁在設計師身上比綁在店上更有說服力。
- **風險與對策**：Footer 上方保留文章精簡列，維持 SEO 內鏈

### D-05 Notion 當 CMS，只管兩種內容

- **決定**：作品集與髮型誌走 Notion，其餘硬寫
- **放棄**：全站可編輯的彈性
- **理由**：單人維護，後台越多越不會用。只有每週會動的內容值得做後台。
- **風險與對策**：Notion API 有速率限制，需做建置時快取

### D-06 設計師頁一律模板化

- **決定**：假設設計師會流動
- **放棄**：為個別設計師客製版面的空間
- **理由**：客製版面在人離職時會整頁報廢。模板化的維護成本遠低於重畫。
- **風險與對策**：以「擅長標籤 + 作品」呈現個人差異，不靠版面差異

### D-07 不執行商標檢索

- **決定**：英文名 MARGIN 不做商標檢索與註冊評估
- **放棄**：命名的法律確定性
- **理由**：MARGIN 為常見英文字，近似案機率高。但本案為作品集模擬案例，不實際營業、不對外招牌、不申請登記，檢索成本無對應效益。
- **若為真實客戶則反之**：商標檢索應在命名定案**之前**完成。命名撞號的代價不只是改名，而是招牌、名片、網域、Google 商家、IG 帳號全部重做，成本遠高於一次檢索。
- **風險與對策**：文件保留此條，作為交付時的風險告知；`marginhair.com.tw` 網域可先行註冊佔位

### D-08 首頁服務卡片不分主次

- **決定**：五個服務類別等重呈現，不加「主力」標記，僅以順序表達（燙 → 染 → 頭皮 → 剪 → 護）
- **放棄**：在首頁直接標示主力服務的機會
- **理由**：主力服務屬「品項」層級（韓系層次燙），首頁卡片屬「類別」層級（燙髮），加標記會讓兩層階層擠在同一區塊。且剪髮是 Persona C 的進站入口，視覺降級會傷到該族群。
- **風險與對策**：主力訊息由卡片描述文案、服務單頁與作品集數量分佈承載，不依賴視覺標記
- **延伸決定**：首頁卡片順序（燙 → 染 → 頭皮 → 剪 → 護）與 `/services` 分頁籤順序（剪 → 染 → 燙 → 護 → 頭皮 → 造型）**刻意不同**。首頁是推薦情境，價目表是查找情境；查找情境依業界慣例排序，尋找成本較低。此差異已於 §6.3 註明，避免日後被當成漏改而「修正」。

### D-09 移除麵包屑，導覽收斂為單層

- **決定**：全站不放麵包屑；Header 改為 Archivo 英文標籤的單層導覽列，不放強調色
  【立即預約】按鈕與 IG 連結；Footer 收斂為版權宣告、示意圖聲明、IG／KAOHSIUNG 三項
- **放棄**：§5 規定的麵包屑、Header 上的第二個預約入口、Footer 的網站地圖與最新文章精簡列
- **理由**：
  1. 站的實際深度只有兩層（列表 → 單頁），麵包屑在兩層結構裡不提供新資訊，
     卻要在每頁頂端多一條橫向元素，違反 §1.4 原則 2「新增元素前，先問能不能拿掉別的」。
  2. §1.4 原則 4 規定每個區塊最多一個強調色按鈕。每頁底部已有固定的預約 CTA 區塊，
     Header 再放一顆等於同一個畫面出現兩個主鍵，強調色也就不再是強調。
     把唯一的強調色留給頁底 CTA，GA4 的點擊歸因也比較乾淨。
  3. Footer 放滿地址、電話、時間、文章列與網站地圖，會讓每一頁的結尾都是最擠的一屏，
     與「留白是主角」直接衝突。這些資訊在 /store 有完整版本。
- **風險與對策**：
  - **預約 CTA 點擊率（§2.2 KPI ≥ 8%）少了 Header 這個入口**，是本決策最大的代價。
    對策是手機 Sticky 預約列（F-02，P0），**2026-09-06 已實作**，補回手機的常駐入口。
    桌機仍只有頁底 CTA 一個入口；上線後看 `cta_booking_click` 的 `location` 分佈，
    若撐不起 8%，優先加回 Header 按鈕。
  - Footer 的最新文章精簡列原是 D-04 為 SEO 內鏈保留的，取消後髮型誌上線時
    需另找位置補內鏈（例如文章頁的「相關文章」與服務單頁互連）。
  - 麵包屑取消後，04-SEO §4.6 的 `BreadcrumbList` 失去對應的畫面元素。
    Google 的結構化資料規範要求 schema 反映頁面上實際存在的導覽，
    因此 `BreadcrumbList` 一併移除，不要只留 schema。
- **補註（2026-09-06，Sticky 預約列實作時）**：
  1. **主鍵不用強調色。** §5 與文案原本寫「主鍵強調色」，但設計系統的 primary 按鈕
     是實心黑（`--surface-solid`）。強調色 `#C8351C` 在站上是**狀態色**——當前頁底線、
     欄位錯誤、已選但接不下的日期、需要漂髮。拿來當行動按鈕會讓那個訊號失效，
     所以 Sticky 列的主鍵沿用既有的 primary 樣式。
  2. **捲到頁底收尾帶時 Sticky 列收起來。** 收尾帶已經有一顆一樣的預約按鈕，
     兩個同時出現只是重複，也違反 §1.4 原則 1「一屏一件事」。
     實作用 IntersectionObserver 觀察收尾帶，沒有收尾帶的頁（設計師頁、作品單頁）
     則一直顯示。
  3. **頁尾加回兩條站內連結**（加入我們、隱私權政策）。這兩頁沒有其他入口，
     孤島頁對 SEO 與使用者都比頁尾多兩個文字連結糟。取消的仍然是網站地圖、
     地址電話與最新文章列——頁尾不會變回「每一頁都以最擠的一屏收尾」。

### D-10 首頁服務區改為價目導引，價目表不做分頁籤

- **決定**：四項連帶調整
  1. 首頁區塊 3 由「5 張服務卡片（名稱＋一句描述＋起價）」改為 4 格純影像＋名稱的
     價目導引，全部連往 `/services`
  2. `/services` 不做分頁籤，五個類別依序直接展開（F-08 本期不做）
  3. 設計師個人頁增加「最近的空檔」區塊，可直接點時段進入預約流程
  4. `/location` 更名為 `/store`
- **放棄**：首頁上的起價資訊、造型類別的首頁曝光、F-08 價目表分頁籤（P1）
- **理由**：
  1. 價目實際只有 9 個品項、5 個類別，分頁籤會讓每一籤只剩 1–3 列。
     §1.4 說每籤最多 8 項是為了防止過長，但過短的分頁籤是純粹的多餘互動：
     使用者得先點一次才知道那一籤只有兩行。直接展開的總長度仍在可滾動範圍內。
  2. 首頁卡片放起價，等於在首頁做一次縮小版價目表，違反 §1.4 原則 1「一屏一件事」。
     首頁區塊 3 的任務改為「這間店做哪些事」，「多少錢」交給 `/services` 一頁回答。
  3. 設計師個人頁是全站最重要的頁（§6.5）。「看完這個人 → 想約他」中間原本還要
     跳到 `/booking` 從第一步選設計師，加上空檔區塊可以少兩步。
  4. `/store` 與導覽列全英文標籤的字長一致（WORKS／STORE／STYLISTS），
     `LOCATION` 在同一列裡明顯過長。
- **風險與對策**：
  - **Persona C（3 秒內找到價格）在首頁看不到任何價格**，多了一次點擊。
    對策：導覽列 SERVICE 一次到達，且 `/services` 頁首就是價格保證那句話。
    若 GA4 顯示首頁跳出率超過 §2.2 的 55%，優先改回「卡片帶起價」，
    而不是回頭做分頁籤。
  - `/location` → `/store` 需同步 04-SEO 的路徑、sitemap 與 Google 商家網站欄位；
    若曾對外露出過 `/location`，需設 301。
- **註**：造型類別在 `/services` 也尚未建立（目前 5 類 9 品項），
  那是缺件不是決策，仍在 backlog。

### D-11 服務單頁改成站上實際的五類，並取消 Before／After

- **決定**：
  1. 五個服務單頁改為 **剪髮／染髮／燙髮／護髮／頭皮養護**，取代 v1.3.1 的
     燙／染／護／頭皮／**接髮**
  2. **不做 Before／After 區塊**，改為列出該項目的實際作品，連往作品單頁
- **放棄**：接髮的服務單頁；Before／After 這個對 Persona B 最有說服力的區塊
- **理由**：
  1. **站上根本沒有接髮這個服務。** 價目表五類是剪／染／燙／護／頭皮，接髮既沒有
     品項也沒有價格，做一頁單頁等於憑空生出一個不存在的服務。
     反過來說，**剪髮是 Persona C（約 15%）的進站入口**，卻是唯一沒有單頁的類別，
     那才是真正的漏洞。
  2. **站上沒有任何 before 素材。** 佔位圖是 Unsplash 的成品照，沒有對應的「施作前」。
     硬做只能拿兩張不相干的照片充數，那比不做更糟——PRD §7.1 已經明訂不可挪用他人
     作品照，而假的 Before／After 在美髮業是實質的不實廣告。
- **風險與對策**：
  - **Persona B（高單價需求客，約 25%）少了「怕花大錢做壞」的直接解方。**
    目前由三處分攤：作品單頁的「需要漂髮」與色號、服務單頁的「你需要知道」
    （寫明不接什麼髮況）、以及各設計師自述裡的判斷標準。接上實拍後應優先補回。
  - 接髮若之後要做，順序是「先進價目表 → 再開單頁」，不要反過來。
- **連帶**：`/services` 每個類別區塊加一條「看{類別}的完整說明」的文字連結，
  否則五頁是孤島。文案 §4 的接髮段落改標為未採用。

## 13. 附錄 A：資料結構定義

此章同時是三件事的依據：**Notion 資料庫欄位**、**作品集篩選功能**、**作品卡片要顯示什麼**。三者共用同一份定義，改一處就要三處一起改。

### 13.1 作品集資料庫（Works）

| 欄位 | Notion 型別 | 必填 | 用在哪 | 說明 |
|---|---|---|---|---|
| 作品標題 | Title | ✅ | 單頁 H1、卡片 | 20 字內，寫髮型不寫感受。例「羊毛捲＋奶茶棕」 |
| Slug | Text | ✅ | 網址 `/works/{slug}` | 英數與連字號，不重複 |
| 狀態 | Select | ✅ | 建置過濾 | 草稿／上線／下架 |
| 封面圖 | Files | ✅ | 網格、卡片 | 4:5，1200×1500 |
| 正面圖 | Files | ✅ | 單頁 | 4:5 |
| 側面圖 | Files | ⬜ | 單頁 | 4:5 |
| 背面圖 | Files | ⬜ | 單頁 | 4:5，染髮作品建議必附 |
| Before 圖 | Files | ⬜ | 單頁對比區 | 有才顯示 Before/After 區塊 |
| **服務類型** | Multi-select | ✅ | **篩選軸 1**、卡片標籤 | 剪髮／染髮／燙髮／護髮／頭皮養護／接髮 |
| **髮長** | Select | ✅ | **篩選軸 2** | 短髮／中長髮／長髮 |
| **設計師** | Relation → Stylists | ✅ | **篩選軸 3**、單頁小卡 | 單選 |
| **髮色系** | Select | ⬜ | **篩選軸 4（P1）** | 棕色系／金色系／粉色系／灰色系／黑色系／紅色系／不適用 |

| 需漂髮 | Checkbox | ⬜ | 單頁提醒 | 影響顧客預期與價格 |
| 使用色號 | Text | ⬜ | 單頁施作資訊 | 例「10/81 + 護色」 |

**衍生欄位（程式產生，不在 Notion 手填）**

- `相關作品` ＝ 同設計師或同風格標籤，取 4 筆

### 13.2 篩選功能規格

| 項目 | 規格 |
|---|---|
| 篩選軸 | 服務類型、髮長、設計師（P0）＋ 髮色系（P1） |
| 邏輯 | 軸與軸之間 AND；同軸多選為 OR |
| 預設 | 全部，依排序權重 → 建立日期新到舊 |
| 網址 | `/works?service=color&length=medium`，可分享、可回上一頁 |
| 無結果 | 顯示「沒有符合的作品」＋【清除篩選】＋ 推薦 4 張熱門作品 |
| 手機 | 篩選收在底部彈出面板，已選條件以 chip 顯示於網格上方 |
| 計數 | 每個選項後顯示筆數，為 0 者停用不隱藏 |
